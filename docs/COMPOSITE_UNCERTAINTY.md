# Composite uncertainty and common-cohort sensitivity (exploratory)
## Scientific objective
Separate specification sensitivity from changes in eligibility and quantify repeated-observed-day variation in the composite and signed peer gap. This does not establish construct validity, sampling error for the census of observed requests, causality or robustness to unreported requests.
## Common cohort
Apply the original v0.1 filtering and first-duplicate rule at the maximum tested horizon, including any custom primary horizon. Retain exactly that cohort for all horizons and weights. Do not prefilter before duplicate handling. The baseline is the primary specification on the same restricted cohort. Report ordinary primary eligible count, common count and exclusions; the restriction may select earlier requests. Existing variable-cohort sensitivity remains available.
## Bootstrap
For each service, group the original primary eligible records by recorded naive creation date, combining all boroughs on each observed day. Draw the same number of observed days with replacement (499, fixed seed 20261125, LCG specified in code), jointly recompute focal and pooled other-borough friction, signed difference and BFS-DAI. Store aggregate day counts and friction sums in memory, no raw rows in exports. Use 2.5%/97.5% linear-interpolated percentile ranges on the 0–100 scale (signed gap -100 to 100). Require original scoreable group, at least eight distinct focal and peer days, and 95% valid draws meeting original count threshold; otherwise withhold. These thresholds are provisional. No multiplicity adjustment, serial-dependence model, measurement-error model or independent population sampling. Days with no eligible requests are not sampled. Treat as exploratory variability under a day-resampling model, not definitive confidence bounds. Existing primary Wilson estimates unchanged; new ranges are separate exports. Independent Python/R replication of new bootstrap and fixed-cohort estimates required before publication.
## Validation
Known-answer fixture with instantaneous closure and no recorded closure, deterministic repeated seeds, small-day suppression, exact cohort counts, duplicate ordering, changed inputs rejected and browser export smoke. No real data analyzed. No network access or service dependencies added.
